# DEVELOPMENT_TASKS: урок 3

## 1. Назначение файла

Этот файл содержит готовую последовательность маленьких задач для агента на третьем уроке курса. Его можно использовать как чеклист или копировать отдельные задачи в opencode.

Правило урока: не давать агенту команду "сделай все приложение". Каждая задача должна иметь понятный результат, ограничения и проверку.

## 2. Общие правила для всех задач

Перед каждой задачей агент должен учитывать:

- источники правды: `PROJECT_SPEC.md`, `IMPLEMENTATION_PLAN.md`, `ACCEPTANCE_CRITERIA.md`;
- перед frontend-изменениями читать и учитывать критерии интерфейса из `ACCEPTANCE_CRITERIA.md`;
- не добавлять Docker до урока 4;
- не добавлять Playwright до урока 4;
- не добавлять E2E-тесты до урока 4;
- добавлять быстрые frontend-автотесты на Vitest/Testing Library там, где они помогают безопасно развивать UI;
- не добавлять changelog и release notes до урока 5;
- не хранить AI API key в коде;
- после изменения сообщать список файлов и выполненные проверки;
- если требуется изменить контракт между backend и frontend, сначала объяснить причину.
