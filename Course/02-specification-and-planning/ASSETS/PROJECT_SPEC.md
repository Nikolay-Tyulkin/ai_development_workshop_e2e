# PROJECT_SPEC: Менеджер задач с ИИ

## 1. Цель продукта

Создать учебное веб-приложение для управления задачами с базовыми ИИ-функциями. Приложение должно показать полный цикл End2End-разработки: frontend, backend, хранение данных, API, AI-интеграция, тестирование, Docker и документация.

Главная цель MVP - дать пользователю простой интерфейс для работы с задачами и показать, как ИИ может помогать формулировать и декомпозировать задачи.

## 2. Границы MVP

В MVP входит:

- просмотр списка задач;
- создание задачи;
- редактирование задачи;
- удаление задачи;
- смена статуса задачи;
- фильтрация по статусу и приоритету;
- текстовый поиск по названию и описанию;
- генерация задач по описанию цели через AI;
- разбиение одной задачи на подзадачи через AI;
- улучшение формулировки задачи через AI;
- локальный запуск frontend и backend;
- хранение данных в SQLite через backend.

В MVP не входит:

- регистрация и авторизация пользователей;
- совместная работа нескольких пользователей;
- роли и права доступа;
- real-time обновления;
- push-уведомления;
- календарная интеграция;
- production-деплой;
- платёжная логика;
- сложная аналитика продуктивности.

## 3. Целевые пользователи

Основной пользователь - участник курса, который запускает приложение локально и использует его как учебный проект.

Вторичный пользователь - преподаватель или ревьюер, который проверяет структуру проекта, работу приложения и качество инженерного процесса.

## 4. Пользовательские сценарии

### Создание задачи

Пользователь открывает приложение, вводит название задачи, описание, приоритет и дедлайн. После сохранения задача появляется в списке со статусом `todo`.

### Работа со списком задач

Пользователь видит задачи в виде списка или карточек. Он может отфильтровать задачи по статусу, приоритету и найти задачу по тексту.

### Обновление задачи

Пользователь открывает существующую задачу, меняет название, описание, статус, приоритет или дедлайн. После сохранения изменения отображаются в списке.

### Удаление задачи

Пользователь удаляет задачу. Приложение запрашивает подтверждение или делает удаление очевидным и обратимым на уровне интерфейса учебного MVP.

### Генерация задач через AI

Пользователь вводит цель, например "подготовить презентацию проекта". AI предлагает список задач, которые можно добавить в приложение.

### Разбиение задачи на подзадачи

Пользователь выбирает крупную задачу и просит AI разбить ее на подзадачи. Приложение показывает предложенный список, а пользователь решает, какие подзадачи добавить.

### Улучшение формулировки

Пользователь вводит черновое описание задачи. AI предлагает более ясную и конкретную формулировку.

## 5. Функциональные требования

### Задачи

- Задача должна иметь `id`, `title`, `description`, `status`, `priority`, `due_date`, `created_at`, `updated_at`.
- `title` обязателен.
- `status` принимает значения `todo`, `in_progress`, `done`.
- `priority` принимает значения `low`, `medium`, `high`.
- `due_date` может быть пустым.
- Пользователь может создать, прочитать, обновить и удалить задачу.

### Фильтрация и поиск

- Пользователь может фильтровать задачи по статусу.
- Пользователь может фильтровать задачи по приоритету.
- Пользователь может искать задачи по `title` и `description`.
- Фильтры и поиск могут применяться одновременно.

### AI-функции

- Пользователь может отправить цель и получить список предложенных задач.
- Пользователь может отправить текст задачи и получить список подзадач.
- Пользователь может отправить черновой текст и получить улучшенную формулировку.
- AI API должен вызываться только через backend.
- API-ключ AI-провайдера должен передаваться через переменную окружения.
- Для тестов и локальной демонстрации должен быть предусмотрен мок или fallback без реальных запросов к AI API.

### Ошибки и состояния

- Frontend должен показывать состояние загрузки.
- Frontend должен показывать понятную ошибку при недоступности backend.
- Frontend должен показывать пустое состояние, если задач нет.
- Frontend должен соответствовать UI/UX-правилам.
- Backend должен возвращать корректные HTTP-статусы и сообщения ошибок.

## 6. Нефункциональные требования

- Приложение должно запускаться локально на машине участника курса.
- Код должен быть понятным для учебного проекта и не содержать лишних абстракций.
- Frontend должен быть адаптивным для desktop и mobile.
- UI должен быть рабочим интерфейсом, а не landing page или декоративной демонстрацией.
- Backend должен иметь ясную структуру API и валидацию входных данных.
- Секреты не должны храниться в репозитории.
- Docker должен быть возможен без серьезной перестройки проекта на четвертом уроке.
- Базовые проверки должны выполняться локально без внешней инфраструктуры.

## 7. Модель данных

### Task

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `id` | integer или uuid | да | Уникальный идентификатор задачи |
| `title` | string | да | Краткое название задачи |
| `description` | string | нет | Подробное описание |
| `status` | string | да | `todo`, `in_progress`, `done` |
| `priority` | string | да | `low`, `medium`, `high` |
| `due_date` | date или datetime | нет | Дедлайн |
| `created_at` | datetime | да | Дата создания |
| `updated_at` | datetime | да | Дата последнего изменения |

Связи между задачами и подзадачами в MVP можно реализовать одним из двух способов:

- простой вариант: AI предлагает подзадачи как отдельные новые задачи без связи с родителем;
- расширенный вариант: добавить `parent_id` для связи подзадачи с родительской задачей.

Для курса рекомендуется начать с простого варианта и не добавлять `parent_id` до появления явной необходимости.

## 8. API на уровне endpoint-ов

### Tasks API

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `/api/tasks` | Получить список задач с фильтрами и поиском |
| `POST` | `/api/tasks` | Создать задачу |
| `GET` | `/api/tasks/{task_id}` | Получить одну задачу |
| `PATCH` | `/api/tasks/{task_id}` | Обновить задачу |
| `DELETE` | `/api/tasks/{task_id}` | Удалить задачу |

Параметры `GET /api/tasks`:

- `status`;
- `priority`;
- `search`.

### AI API

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `POST` | `/api/ai/generate-tasks` | Сгенерировать список задач по цели |
| `POST` | `/api/ai/split-task` | Разбить задачу на подзадачи |
| `POST` | `/api/ai/improve-task` | Улучшить формулировку задачи |

AI endpoint-ы должны возвращать структурированные данные, а не только свободный текст.

## 9. Технический стек

Frontend:

- React;
- TypeScript;
- Vite;
- CSS Modules или обычный CSS без тяжелой UI-библиотеки на старте.

Backend:

- Python;
- FastAPI;
- Pydantic;
- SQLite;
- SQLAlchemy или SQLModel.

AI-интеграция:

- backend-сервис для обращения к AI API;
- переменная окружения для ключа;
- мок-режим для тестов и демонстрации.

Тесты и запуск:

- backend-тесты через pytest;
- базовые frontend-автотесты через Vitest и Testing Library на третьем уроке;
- frontend-проверки через npm scripts;
- Playwright E2E и Docker добавляются на четвертом уроке курса.

## 10. Ограничения

- Не начинать реализацию без согласованного `IMPLEMENTATION_PLAN.md`.
- Не добавлять авторизацию в MVP.
- Не хранить AI API key в коде, `.env.example` может содержать только имя переменной без реального значения.
- Не усложнять архитектуру микросервисами.
- Не добавлять внешнюю production-БД до Docker-этапа.
- Не добавлять полноценную систему подзадач, если это мешает завершить MVP.

## 11. Риски

| Риск | Влияние | Снижение риска |
| --- | --- | --- |
| Слишком широкий MVP | Проект не успеет дойти до рабочего состояния | Держать авторизацию, роли и аналитику вне MVP |
| Нестабильный AI API | AI-функции сложно проверить | Добавить мок-режим и структурированные ответы |
| Секреты попадут в код | Нарушение безопасности | Использовать переменные окружения и `.env.example` |
| Frontend и backend разойдутся по контракту | Интеграция сломается | Зафиксировать endpoint-ы и схемы данных до разработки |
| Сложная модель подзадач | Увеличение объема backend и UI | Начать с генерации отдельных задач |

## 12. Открытые вопросы

- Нужен ли `parent_id` для подзадач в первой версии или достаточно отдельных задач?
- Нужно ли подтверждение удаления или достаточно простой кнопки удаления в учебном MVP?
- Какой AI-провайдер будет использоваться в демонстрации курса?
- Должен ли мок AI включаться автоматически при отсутствии API-ключа?
